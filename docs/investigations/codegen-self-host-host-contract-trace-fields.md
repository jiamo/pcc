# Investigation: self-host codegen trace fields missing from host contract

## Status
resolved (2026-05-23)

## Problem description
In the `PCC_DEBUG_CODEGEN_PHASES=1` self-host stress path, the stage1 compiler generated by `build_closed_world_context` can raise
`PCC-PY-COMPILE-001` at startup; the source error is `AttributeError`:
`_codegen_trace_enabled` or `_codegen_current_stmt_index`.

The minimal reproduction is to run a bootstrap compile of a simple script after the stage1 smoke step.

## Repro (minimal)

- Use reproducible instance file `/tmp/unsupported_trace.py`:
```python
from pcc.llvm_capi.compat import ir

def f():
    x = ir.Argument(1, 2)
```
- Run this with the old host contract:
```bash
env -u LC_ALL build/bootstrap-pytest-self/pcc1 \
  --backend self --python-libpython=off --ir-scaffold=on \
  /tmp/unsupported_trace.py -o /tmp/unsupported_trace_bin
```
- The failure summary is:
```text
error: PCC-PY-COMPILE-001: [python-frontend] _codegen_trace_enabled
```
or
```text
error: PCC-PY-COMPILE-001: [python-frontend] _codegen_current_stmt_index
```

## Root cause
The full/bootstrap run triggered by `tests/python/test_pcc_bootstrap_full.py` uses self-host stage1.
`pcc/py_frontend/pipeline.py` fills host class fields for `L1CodeGen` in
`build_closed_world_context()` through `L1_CODEGEN_HOST_ATTRS`.
The new trace debug fields are initialized only in `Layer1InitMixin._init_l1_state`,
but the initially added host attr names contained the misspelled prefix ` _codegen_trace_current_*`,
while the actual read/write fields are `_codegen_current_*`.
As a result, the stage1 closure class lacked the matching slots, writes fell into the fallback path, and `AttributeError` was raised.

## Fix
- Modify `pcc/py_frontend/codegen/host_contract.py`:
  - Correct names such as `"_codegen_trace_current_expr_kind"` to
    `"_codegen_current_expr_kind"`.
  - Add `"_codegen_current_module_name"`.
- Keep `L1CodeGen` trace-field initialization and `generate()/_emit_stmt` context-recording logic unchanged.

## Validation
- `env -u LC_ALL uv run pytest tests/python/test_pcc_bootstrap_full.py::test_full_three_stage_bootstrap_self -q -n0`
  - pass
- `env -u LC_ALL uv run pytest tests/python/test_codegen_debug_trace.py -q -n0`
  - pass
- Run the trace script again with stage1 and observe complete `PCC_CODEGEN_EXCEPTION`/`PCC_CODEGEN_BREADCRUMB` output, with no `AttributeError`.

## Notes
This fix is basic convergence between the host-contract schema and the hot path; it is not a semantic algorithm change.
