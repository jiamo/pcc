## Interpretation

Stage1 default behaviour today closes the import graph at `pcc.__main__` + `pcc.cli_bootstrap` (2 files, ~25 fallbacks). Those 25 fallbacks are the IR-visible cost of `cli_bootstrap` calling `compile_python(...)` via dynamic dispatch; the rest of the frontend is not in the native compile graph at all and runs as CPython-interpreted code linked through the same `libpython` that backs the fallback shims.

Pulling more files into the native compile graph (this probe) exposes the `py_cpy_*` density that already lives inside `layer1.py`, `runtime_abi.py`, and `pipeline.py` — it does **not** remove libpython, it just shifts who is using it. Pure-native frontend self-compile is therefore not a walker default flip; it is a long-running effort to remove dynamic Python idioms from those hot files.

Tracking goal: `tight` total fallback count is the headline metric to drive down. Re-run this probe periodically; commit the report so deltas are visible in git history.
